  配置するのは白ヤギ。黒ヤギの【進めてよい】のあとに行う。岩城さんにコマンドは渡さない
  実行は Claude Code の Bash ツール（gcloud・git）。PowerShell ではない


■ 0. 前もって知っておくこと

  サービス名        kartelog（Cloud Run・asia-northeast1）
  プロジェクト      gen-lang-client-0979357970（gcloud の既定のまま）
  image の置き場    asia-northeast1-docker.pkg.dev/gen-lang-client-0979357970/homis-karte-writer/app-kartelog:v<版>
  入口              app.nhw.jp/kartelog/（ロードバランサー＋IAP。配置で触らない）
  設定              環境変数（RECORD_BUCKET・IAP_AUDIENCE・QUEUES・DX_ADMINS・FM_HOST・FM_DB）と
                    Secret（fm-sun-patient-user・fm-sun-patient-password）は Cloud Run に入っている。
                    配置では --image だけを変え、設定は渡さない（渡すと上書きして消える）
  版の場所          main.go の const version・public/app.js の APP_VERSION・public/sw.js の CACHE。
                    3 つがそろっていないと試験が赤になる（test/app_clinic_test.cjs）
  gcloud の注意     --source は使わない（このプロジェクトでは通らない）。builds submit --tag → run deploy --image


■ 1. 配置の前に（白ヤギ）

  1-1. 黒ヤギの【進めてよい】が出ていること（指摘で直したら再レビュー）
  1-2. 版と改定履歴がそろっていること（main.go 先頭・const version・app.js・sw.js・docs\SPEC_v3_cloud.md の表と改定履歴）
  1-3. 試験が通ること
         cd "G:/マイドライブ/Antigravity-PJ/Homis自動カルテ生成/app-kartelog"
         node test/app_clinic_test.cjs        → ALL OK
         go test -count=1 ./...               → ok
  1-4. 配置する中身を commit 済みであること（git status で app-kartelog に M が無い）
  1-5. 今の本番のリビジョン名を控える（戻すときに使う）
         gcloud run services describe kartelog --region asia-northeast1 --format="value(status.latestReadyRevisionName,spec.template.spec.containers[0].image)"


■ 2. ビルド（commit 済みの中身だけを C: に出してから送る）

  G: のフォルダをそのまま送ると、commit していないファイル・desktop.ini・img_source も混ざる。
  git archive で commit 済みの app-kartelog だけを C: の作業場所に出して、そこから送る。

    V=0.3.5   ← 配置する版
    W="C:/Users/setup/AppData/Local/Temp/kartelog_build_$V"
    rm -rf "$W" && mkdir -p "$W"
    cd "G:/マイドライブ/Antigravity-PJ/Homis自動カルテ生成"
    git archive HEAD app-kartelog | tar -x -C "$W"
    cd "$W/app-kartelog"
    grep -n 'const version' main.go           → 配置する版と同じか目で見る
    gcloud builds submit --tag asia-northeast1-docker.pkg.dev/gen-lang-client-0979357970/homis-karte-writer/app-kartelog:v$V

  終わりに STATUS SUCCESS が出れば成功。


■ 3. 配置（image だけを入れ替える）

    gcloud run deploy kartelog --region asia-northeast1 --image asia-northeast1-docker.pkg.dev/gen-lang-client-0979357970/homis-karte-writer/app-kartelog:v$V

  「Service [kartelog] revision [kartelog-000xx-xxx] has been deployed and is serving 100 percent of traffic.」が出れば成功。


■ 4. 配置のあとの確認（白ヤギ）

  4-1. リビジョンと image
         gcloud run services describe kartelog --region asia-northeast1 --format="value(status.latestReadyRevisionName,spec.template.spec.containers[0].image)"
         → 新しいリビジョン名・image が v<版>
  4-2. 起動の記録（版と設定がそろって起きたか）
         gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="kartelog" AND textPayload:"listening"' --limit 3 --freshness 30m --format="value(timestamp,textPayload)"
         → 「kartelog <版> listening on :8080 bucket_set=true queues=… admins=… fm=true」
           bucket_set=false や fm=false なら設定が抜けている → 5 で戻す
  4-3. エラーが出ていないか（配置後 5 分）
         gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="kartelog" AND severity>=ERROR' --limit 10 --freshness 10m
  4-4. 画面（岩城さんにお願いするのはここだけ）
         app.nhw.jp/kartelog/ を開いて F5 → 見出しの横が「版 <版>」になっているか。
         「新しい版があります。F5 を押してください」が出たら、もう一度 F5


■ 5. うまくいかないとき（前のリビジョンに戻す）

    gcloud run services update-traffic kartelog --region asia-northeast1 --to-revisions <1-5 で控えたリビジョン名>=100

  戻したら、何が起きたかを WORK_LOG とこの手順書の「配置の記録」に書く。
