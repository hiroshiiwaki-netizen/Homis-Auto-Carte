■ 2. 今あるもの（9/4〜9/8 に済んでいる）

  - Cloud Run サービス homis-karte-writer（東京・4Gi/2CPU・timeout 300・concurrency 1・蓋 max-instances 3・min 0）
  - 合言葉（X-Writer-Key）・HOMIS の ID/PW は Secret Manager。HOMIS は専用の「おひさまロボット GCP」アカウント
  - 失敗の扱い（仕様 7章）: 新規ボタンのあとは中でやり直さない／orderId で二重を断る（試験で 2回目 409）
    空カルテ疑いは DX に Chat（Webhook は Secret・未作成）
  - 試験: 1件 約45秒／別の患者3人同時は3枚／同じ患者の同時は1枚に重なる（HOMIS の性質）
  - 結果シート「HOMIS書込結果」は試験用の別ブック。ナビ（GAS）は未接続


■ 3. 決めたこと（v0.2・黒ヤギの意見つき）と、岩城さんに決めていただくこと

  決め1  ナビから Cloud Run をどう呼ぶか → 案B（Cloud Tasks の列を挟む）に一本化（黒ヤギも強く推し）

    案B: ナビは「順番待ちの列」（Cloud Tasks・東京）に入れるだけ。列が Cloud Run を1件ずつ呼ぶ（同時 1・再試行 0）
      - 今の垂水と同じ「1件ずつ」なので、同じ患者の重なり・蓋の 429・ナビの待ち時間の問題が出ない
      - 列が Cloud Run の認証を代わりにする（IAM。合言葉も残す）
    案A（ナビから直呼び）は採らない: 集団40名を1回の撮影完了で順に呼ぶと 40×約45秒 ＝ 約30分で、
      GAS の1回の実行の上限 6分（公式 quotas: Script runtime 6 min / execution）を必ずこえる。
      UrlFetch の1回の待ちの上限は公式の制限ページに記載なし【推測: 約60秒と言われる】

    【岩城さんに確認】列の中の一時保存（東京・届けたら消える）が「保存はしない」（9/4 決定）の範囲に入るか

  決め2  「書けた」の知らせ方 → Cloud Run が書き終えたら、ナビの doPost を呼ぶ（今の垂水と同じ流れ）（黒ヤギ指摘1）
      - ナビの updateHomisLink_ ／ sendGroupCompleteNotification_ をそのまま使える。ナビに時間トリガーを入れない
      - v0.1 の「ナビが結果シートを1分おきに見る」はやめた
        （黒ヤギの「1日90分の上限で止まる」は一般アカウントの値。nhw.jp は Workspace で 6時間/日（公式 quotas）。
         上限の心配ではなく、仕組みを今と同じにできるので採った）
      - 知らせの失敗（穴3）の手当て: Cloud Run は応答が無い／5xx のときだけ 3回まで間をあけて再送。
        だめなら DX の Chat に「撮影完了 Chat が出ていない注文」を知らせる
      - 二重 Chat の手当て（必須）: 今の updateHomisLink_ は2回呼ばれると撮影完了 Chat も2回出る（Order.gs 2162〜2248行。
        「送った」の印が無い）。ナビ側で「この注文は通知済み」をスクリプトプロパティに覚え、2回目は Chat を出さない

  決め3  集団のまとめ通知
      - 主: ナビの updateHomisLink_ が、その回の一括完了で覚えた注文（GRP_BATCH_）が全員そろったら sendGroupCompleteNotification_ を出す
        （失敗した人も Cloud Run は空の URL で知らせるので、数はそろう＝今の垂水と同じ）
      - 予備: 全員そろわないまま最後の知らせから10分たったら DX の Chat に知らせる（人が判断。自動では全員に送らない）
      - 今の sendGroupCompleteNotification_ は「覚えが無いと全員に送る」。GCP のときは覚えが無ければ送らないように分ける（二重送信を防ぐ）

  決め4  切り替えの単位 → 個別も集団も一度に（スクリプトプロパティ HOMIS_WRITE_MODE=3。戻すときは 1。デプロイ不要）（黒ヤギも同意）

■ 5. 切り替えの手順（フェーズ3・平日の朝 9時台）

  1. 撮影完了が入っていない時間を選ぶ
  2. 垂水の監視フォルダ（Homis登録データ）の未処理 JSON が 0件であることを確かめる（黒ヤギ指摘5）
  3. スクリプトプロパティ HOMIS_WRITE_MODE=3
  4. 最初の1件で、列 → Cloud Run → HOMIS → 撮影完了 Chat（1回）まで確かめる
  5. 切り替えのあとに垂水のフォルダへ新しい JSON が来ないこと（MODE=3 ではドライブに置かない）を確かめる
  戻すとき: HOMIS_WRITE_MODE=1。列に残っている分は、Cloud Tasks のキューを止めて（pause）から垂水へ戻すかを決める
            （同じ注文を両方で書かないため。列の中の注文番号を見て、垂水のフォルダに JSON を置き直す手順を用意する）
